# Development progress

Updated 13 October 2026. Version 0.1.0 is an early development build. The approved first release still includes the later reliability, export and integration stages in PRODUCT-PLAN.html.

## Implemented and exercised

- A native Windows Tauri application with a Rust backend, SQLite persistence and a React/TypeScript interface. The same interface has a browser preview using separate IndexedDB data.
- The Library and Reader layouts, independently collapsible/resizable panels, tabbed inspector, selection tools and persistent appearance settings. Library, Settings and the full Bookmarks page hide the inspector and its resize handle without changing the reader's saved panel state. The Library appearance shortcut opens Settings. Unfinished note drafts survive new text selections.
- Library search, sorting, collections, favorites, bulk selection, duplicate detection and recoverable Trash.
- Sidebar controls create persistent empty collections and delete named collections with Undo. Deletion moves active and trashed members to Unsorted while preserving their content and Trash status. Built-in views and Unsorted cannot be deleted. Names reject empty, duplicate and reserved entries. Imports and pasted documents use the selected named collection, and Reader details offer a collection selector.
- TXT, UTF-8 Markdown, pasted text and unprotected text EPUB imports. EPUB order follows its spine. Embedded active content is inert. Current limits are 32 MB input and 64 MB expanded EPUB content; larger files are rejected explicitly.
- Chapter navigation, bounded passage rendering, saved narration position, colored underlines, bookmarks, margin notes, grouping, search and annotation export. Stable paragraph/text-offset anchors survive font and theme changes.
- Spoken-version editing accepts replacements against original paragraph ranges. Save and Reset are explicit; an empty saved version skips that passage. Source text, metadata and annotation anchors are preserved. Separate edits in a paragraph retain original offsets, and a selection touching an existing replacement expands to cover that replacement. Unsaved drafts survive inspector-tab and selection changes within the session. Playback, selection reading and previews use the same narration resolver. Saved edits and rule changes discard obsolete playback units.
- Roman numerals in numbered headings are converted to Arabic numbers for the speech model. This defaults on and is reversible in Speech settings. Canonical and Unicode Roman forms are supported; ordinary body text is unchanged, and explicit manual wording takes priority. Ambiguous titles beginning with a pronoun or initial are conservatively left alone.
- Twelve annotation colors, search across note text, marked text, full paragraph context, groups and book titles; current/all-book scope; type/color filters; alphabetical, forward/reverse book-position and recent sorting. Cards show actual section headings and paragraph positions, and can expand the full source paragraph. A single temporary bookmark retains the reader's original book, narration position and viewport offset through multiple note/bookmark jumps, including across books. Return to reading restores that location and clears the marker. Dismiss and app exit also clear it.
- Twelve app palettes plus independent paper, white, sepia and night reading surfaces. Reading page width is adjustable from 600 to 2200 pixels, with a full-width option; it always fits the available reader space. Paper texture and background motion can be disabled; reduced-motion preferences are respected. Background thumbnails retain their image on hover, with an outer accent frame and a small preview zoom.
- A faceted lavender crane derived from the first approved mockup, used for the interface and native app icon. Optional moonlit lake artwork.
- Appearance includes paper brightness from 50% to 150%, default 100%. Only the paper background and texture are filtered; text, annotation colors, surrounding artwork and app controls retain their colors. Each scene remembers brightness alongside its reading surface, and resetting scene defaults restores 100%.
- Four additional seasonal backgrounds preserve the same lake composition: Spring morning, Summer evening, Autumn dusk and Winter daylight. Spring uses petals, lake mist, mountain fog, ripples and high clouds; summer uses fireflies, mountain haze, ripples, cabin lights, a moon cloud and occasional fish-feeding rings; autumn uses leaves, lake mist, mountain fog, ripples and cabin lights; winter uses snow, lake mist, mountain fog, ripples and cabin lights. Every scene remembers the user's palette, reading surface, paper texture, alpha, motion setting and effect switches. First visits use the screenshot-approved defaults listed in README.md. Returning restores saved choices; a reset button restores the current preset. Existing customized settings are retained.
- Optional Current season and Random at startup modes. Seasons use local calendar months and an explicit northern/southern hemisphere preference, with midnight and window-visibility rechecks. Random mode chooses a different illustrated lake scene once per launch. Manual thumbnail selection disables automatic selection. No location or network access is required.
- Seasonal motion is more visible while remaining slow: 24 spring petals, 24 autumn leaves, 42 snowflakes and 16 larger fireflies spread across the summer lake. Fog, ripples and cabin lights have stronger opacity. Summer feeding events create three concentric rings at varied open-water positions every 28 to 55 seconds after an initial 10 to 22 second wait. Only the event itself updates React state; hidden/reduced-motion windows cancel the timer and remove rings. Disabling the effect, selecting another scene or setting opacity to zero also cleans up the timer.
- Background opacity from 0 to 100 percent affects only the artwork and decorative overlays. Twelve brighter petals drift from right to left with a gentle downward fall. Two lake-mist layers, two mountain-fog layers, three small ripple patches, a softly fluctuating cabin glow and an occasional cloud across the moon use compositor transforms and opacity. Every effect has a switch. A shared aspect-ratio stage keeps the overlays aligned with the artwork through window resizing and cropping. Motion defaults on for new settings; an existing saved off preference remains off. Hidden windows pause all 21 animations; reduced-motion mode hides the overlays. Zero opacity and the None scene remove them entirely. There is no video decoder, full-scene frame sequence or per-frame React update.
- A voice catalog with language, voice gender and style filters, name/accent search, favorites and sorting. This local installation has eight existing English voice profiles. The catalog supports adding other languages through metadata; no multilingual catalog or voice pack is distributed yet.
- An isolated local Qwen worker with passage-by-passage synthesis, one-passage read-ahead, pause, stop, seek within the current passage, speed/volume and passage highlighting. Only current and nearby playback audio is retained in memory.
- Startup voice preloading is enabled by default and can be disabled in Settings. The app remembers the voice actually used for playback, including a book-specific choice. Model, voice prompt and CUDA warmup run without blocking Library interaction. Opening a book or starting playback preserves a prepared idle worker. Shutdown rejects queued work and terminates/reaps the app's worker, including the Windows Python launcher process tree.
- Cover editing from a small bottom-left hover/focus button on Library covers and the Reader's Document inspector. PNG, JPEG and WebP artwork is copied and resized into library metadata. EPUB 2/3 embedded raster covers are retained before generation is considered. Generated covers show the app's title and author layout; uploaded/imported artwork is shown intact. The editor supports a custom description, random regeneration and cancellation, keyboard focus trapping and inert background controls.
- Optional local SD-Turbo cover generation through a separate stable-diffusion.cpp process. Automatic generation is enabled by default for new imports and pasted documents without artwork; existing documents can be regenerated manually. The model loads only for a job and exits after each image. Speech is unloaded before image generation, and Play cancels a cover job before loading speech. Close and timeout reap the image process. Setup is isolated from Maeve. The tested F16 model is about 2.7 GB on disk, with a 5.2 GB setup download; Q4 produced artifacts and was rejected. See COVER-GENERATION.md for installation, attribution and model terms.
- Reader focus mode now toggles to a collapse icon and restores the saved panel visibility and widths. Entering focus mode does not overwrite those preferences. Escape also restores the layout.
- Selecting a new voice stops current playback, discards old audio/read-ahead and immediately unloads the old worker. Play resumes from the current sentence with the selected voice. A default-voice choice also applies to the currently open document. Optional startup default-voice randomization is restricted to installed voices in the last selected language, remembers specific language filter choices, and integrates with the optional startup preload. Document-specific saved voices retain their normal priority when reopening a document.

## Validation evidence

Windows is the only native runtime exercised so far. Linux source support and Windows/Ubuntu CI definitions are present, but CI has not run and no Linux installation was available for native testing. M0's Linux, packaging and full assistive-technology gates remain open.

The foundation Windows check passed 8 TypeScript unit tests, 3 Rust storage tests and 5 browser workflow tests. The expanded ambient-background update passed the 8 TypeScript tests and 9 browser workflows. New checks cover default-on motion, all effect toggles, opacity persistence, hidden-page pause, reduced motion, thumbnail hover, inspector visibility and restoration, page-width persistence and narrow-window fitting, scene alignment at three aspect ratios, and leftward petal motion. The production frontend and native executable builds also succeeded. The suite covers document normalization and bounded speech segmentation (including a one-million-character fixture), voice filtering, SQLite persistence, annotation durability, import order and inert content, Trash/restore, appearance persistence and keyboard operation. Automated axe checks pass for the tested default Library and Reader views. This does not certify every theme or replace screen-reader testing.

The ambient renderer was profiled in headless Chromium at 1480 x 950 and 3840 x 2160. Four-second steady-state samples recorded zero layouts, style recalculations and layer paints with all effects enabled. Chromium reported accelerated transform/opacity animations; all 21 animations were paused in the hidden-page check. These are renderer checks, not GPU-power measurements, native Linux validation or a TTS-throughput comparison. Run `npm run dev`, then `node scripts/measure-ambient.mjs` to repeat. Results are saved in .local/ambient-performance.json, with the latest checked sample copied to docs/ambient-performance.json. The implementation follows the [browser animation performance guidance](https://web.dev/articles/animations-guide) to animate transforms and opacity without continuously repainting the underlying artwork.

The native Windows app loaded all eight local voice profiles, synthesized actual WAV output, played through the UI, paused and sought within a passage. On the development machine's NVIDIA GeForce RTX 4080 SUPER, one short cold synthesis took 9.06 seconds and produced 3.28 seconds of audio. The next warm synthesis took 0.65 seconds and produced 1.84 seconds of audio. These are small smoke-test samples, not sustained audiobook benchmarks or promises for other hardware. Catalog language, gender, style, search and favorite controls were also exercised in the native WebView.

The seasonal and startup-preload update passed 11 TypeScript tests, 4 Rust tests and 15 browser workflows. It adds all-season effect and asset checks, per-scene appearance restoration across restarts, preload-setting persistence, warm-worker retention, remembered playback voice and cancellation of late synthesis results. The Windows build succeeded. Native checks confirmed startup loading, a 0.0015-second repeated prepare request, and 0.87-second warm synthesis for 1.92 seconds of audio. Closing the test window during generation removed both Python processes and the worker's GPU process entry. Reopening with preloading disabled started zero workers. The original startup preference was restored afterward. Windows WDDM did not expose per-process VRAM bytes, so no total-system memory delta is claimed.

All four seasonal scenes were also profiled at 3840 x 2160. Four-second animated samples used 1.69 to 2.99 milliseconds of renderer main-thread task time, with zero layouts and zero layer paints. There were 1 to 3 style recalculations per sample, rather than a repaint every frame. All 13 to 32 animations paused while hidden. This is a Chromium rendering check, not a GPU-power or TTS-contention benchmark. Repeat with `node scripts/measure-ambient.mjs http://127.0.0.1:1420 --seasons`; the checked output is docs/season-performance.json.

The stronger-motion and automatic-scene update passed 16 TypeScript tests and 19 browser workflows. It adds calendar boundaries in both hemispheres, a live midnight rollover, manual override, random selection once per launch without repeats, screenshot defaults, restoration of custom reading surfaces, legacy profile compatibility, opacity keyboard direction/endpoints, and fish-event scheduling, expansion, cleanup and reduced-motion/visibility behavior. The frontend and Windows release executable builds succeeded. Visual review covered the four seasonal Library views plus wide and narrow Reader inspectors. The existing running app was left open; the rebuilt executable loads on its next launch.

Updated 4K renderer samples recorded 3.22 to 6.40 milliseconds of main-thread task time over four seconds with seasonal animation, and 7.67 milliseconds with feeding rings expanding. These samples had zero layouts and zero layer paints, with 3 to 11 style recalculations, and reported accelerated transform/opacity animation. All 23 to 50 continuous animations paused while hidden; the fish timer stopped. The occasional creation of a new ring group is outside these steady-state samples and can incur one layout/paint, rather than repainting each frame. These measurements do not establish GPU power use or native Linux behavior. The updated measurements, including the summer feeding sample, replace docs/season-performance.json.

The cover, focus and voice-switch update passed 19 TypeScript tests, 25 browser workflows and 5 Rust tests. Checks cover hover positioning, cover persistence, invalid SVG rejection, embedded EPUB art, cover-editor accessibility, enabled/disabled automatic generation, random regeneration seeds, exact panel restoration, same-sentence voice replay, old read-ahead disposal, worker unloading, default-voice selection with a document override, and language-restricted startup choices. The final Windows build returned a valid generated PNG in 2.32 seconds on the development machine and displayed the previously saved cover after reopening its isolated library. The brightness and collection-controls update passed all 19 TypeScript tests and 27 browser workflows.
